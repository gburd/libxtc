# M4.5 -- fast fiber context-switch ASM (SHIPPED)

**Status:** SHIPPED.  The x86-64 SysV and Win64 MS-PE fcontext
implementations are complete and tested.  This document records the
history and remaining arch work.

## What shipped

- `src/os/asm/fctx_x86_64_sysv.S` -- Linux, *BSD, illumos
- `src/os/asm/fctx_x86_64_ms_pe.S` -- Windows x64

Both implement `make_fcontext` / `jump_fcontext` from scratch without
vendoring Boost.Context.  The implementation follows the Sys V / MS
ABI spec exactly and passes round-trip tests.

## Performance

- Before: ~600 ns per context switch (POSIX ucontext on x86-64 glibc)
- After: ~30 ns per context switch (fctx ASM)

## Architecture coverage

Hand-written fctx assembly (make_fcontext / jump_fcontext) now exists
for the major PostgreSQL-supported CPU families.  Each fctx_<arch>.S
self-guards on its target macro and compiles to an empty object on
other arches; the x86_64 files remain the reference.  Verification
status, established by cross-compiling a round-trip harness (transfer
arg threaded through, callee-saved integer AND floating/vector
registers preserved across a switch) and running it under qemu-user:

| arch | ABI | assembles | runtime-verified |
| ---- | --- | --------- | ---------------- |
| x86_64 | SysV / MS PE | yes | yes (native, test_fctx) |
| aarch64 | AAPCS64 | yes | yes (qemu, glibc AND musl-static) |
| ppc64le | ELF v2 | yes | yes (qemu) |
| riscv64 | lp64d | yes | yes (qemu) |
| s390x | z-ABI | yes | yes (qemu) |
| arm (32-bit) | AAPCS / EABI hard-float | yes | NO -- a round-trip register-preservation bug remains; do not rely on it yet |
| sparc64 | UltraSPARC V9 SysV | yes | yes (native, UltraSPARC sun4u / OpenIndiana, gcc 13.4.0 AND clang 21.1.8) |

The musl aarch64 static run is the headline result: it proves the
stackful-coroutine substrate works on the exact no-ucontext target
(musl deliberately omits ucontext), with or without glibc.

Still on ucontext fallback (no fctx asm written): mips64,
loongarch64, and macOS ARM64 (which needs a Mach-O `*_macho_gas.S`
variant of the AArch64 file).  These are added as profiling demands.

Known follow-ups: fix the arm 32-bit round-trip (the integer
callee-saved restore does not survive a switch under qemu-arm).

The sparc64 file is now runtime-verified.  It was assembled and run
natively on a real UltraSPARC sun4u host (OpenIndiana/illumos 5.11,
gcc 13.4.0 and clang 21.1.8, 64-bit -m64), with the same round-trip
fiber harness used for the other arches (transfer arg threaded through
every jump, a coroutine yielded and resumed five times, saved state
intact across each switch) -- 20/20 reliable passes under each
compiler at -O0 and -O2.  The first hand-written draft bus-errored on
the very first store in make_fcontext: a SPARC V9 %sp must keep its
BIASED address (%sp + 2047) 16-byte aligned, so a naively 16-aligned
raw %sp makes every [%sp + BIAS + k] access misaligned.  The revision
bias-aligns the stack pointer, carves a valid run frame for fn,
threads the resume %sp through the saved %fp so the trailing "restore"
lands fn on a real stack, stores fn-8 so "ret" (jmpl %i7+8) enters fn,
and flushes the register windows AFTER writing %fp/%i7 so the spilled
image left on the outgoing stack is self-consistent.

## Build integration

- `XTC_HAVE_FCTX_ASM` is defined when the platform has native fctx.
- `evt/coro_uctx.c` uses fctx when available, ucontext as fallback.
- `test/m4/test_fctx.c` validates round-trip correctness.
